# Interactive TV search delivery

An episode or season interactive search now uses two reads of `GET /api/v3/release/tv` with one `searchId`. The first read sets `preview=true` and returns after the first nonempty provider query finishes; the second read waits for the same search to finish and replaces the preview list. Both reads run TV download decisions against the releases they return. The preview does not update episode last-search times; the complete read does.

The in-flight search is shared by `searchId`, media kind, translated criteria, media tags, and the selected indexer configuration. A completed session stays available for ten minutes so a fast first stage cannot cause a duplicate refresh query when the second read arrives. The session runs each indexer's criteria in the existing sequential order through `ReleaseSearchService`, including its rate-limit checks. Standard and anime TV title criteria place the canonical series title first, then retain every alternate. The existing ID-first tier and stop-after-a-nonempty-tier behavior remain.

Interactive provider query responses are cached for two minutes. The key includes media kind, all criterion fields, scoped categories, indexer settings and capabilities, and proxy configuration. The `refresh=true` query option and the TV search Refresh button bypass this cache. The cache holds raw provider releases; parsing, matching, and acceptance decisions run on every response. Automatic searches and RSS do not use it. An empty response is cached for two minutes too, including an empty response caused by a transient provider failure or rate limit; Refresh forces a fresh attempt subject to the provider's rate limit.

Logs record the preview and complete API response wall times, the provider-search wall time, per-indexer wall time, criterion calls, cache hits, and successful provider request counts. Query logs identify title variants by ordinal (`0` is canonical, `1+` are alternates), and TV decision logs count accepted results by variant. The logs omit query titles and release details. Failed provider attempts may not report their HTTP request count because the indexer layer does not return a query list on failure.

The controlled test holds the last query open, proves the first result is returned before it finishes, then proves the complete response contains both results with three total criterion calls. This is a delivery and query-count proof, not a production latency measurement. No live indexer search was performed for this change.
