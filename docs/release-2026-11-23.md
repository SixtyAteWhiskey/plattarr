# November 2026 production baseline

This release hardens the existing Movies, TV, Music, shared-indexer, and Hygiene
workflows. It is **not full Cleanuparr feature parity**. See the
[capability comparison](hygiene-parity-2026-11-23.md) for implemented behavior and
the remaining feature work.

## Changes

- Pause Hygiene strikes, removals, content actions, and import rescue when
  qBittorrent reports a disconnected network or an unreadable modern connection
  status. Recheck connectivity immediately before removal and preserve recovery
  records during the outage. Ordinary failure processing honors the network
  hold and defers to an active Hygiene failure rule's threshold and safeguards.
- Allow release downloads from an explicitly configured local indexer origin.
  Continue rejecting unrelated private destinations and private redirects to a
  different host, port, or scheme. Both the indexer and downloader fetch paths
  use this boundary.
- Improve light-theme contrast, label icon controls, keep ordinary buttons from
  accidentally submitting forms, and preserve Hygiene tab selection in links.
  Search schedule controls use the shared form and button styles.
- Use Plattarr as the default instance name while preserving configured names.
- Update affected frontend build dependencies, and pin the vulnerable glob
  consumers to patched versions. The pins are scoped so older consumers keep
  their existing API shape.
- Scan added commit history for secrets before CI validation. Exclude runtime
  configuration, databases, keys, and private bundles from Git and image inputs.
  Include Common unit tests in the standard verification command.
- Stop copying complete GitHub event payloads into build provenance. Retain
  minimal image provenance, verify it after publication, and disable automatic
  uploads of detailed Docker build records.
- Repair the disposable Hygiene proof to use the supported three-strike minimum
  and real strike intervals, including both release-fetch paths.

## Release checks

The release gate includes an analyzer-enabled backend build, Common/API/Host/Core
unit tests, frontend type and style checks, a production frontend build,
dependency auditing, and the disposable API and browser proofs. GitHub CI also
builds and checks the completed Linux images for both architectures, scans them
for high/critical vulnerabilities, and checks cover processing on Windows and
macOS.

Browser checks cover desktop and mobile layouts, light and dark themes, and
color-impaired mode. They check rendered content and HTTP failures as well as
JavaScript errors and horizontal overflow. They are an accessibility and
usability smoke check, not a complete accessibility certification.

## Upgrading

Back up the databases, configuration, and Compose file before replacing the app
container. Pin the reviewed `sha-…` image from the release instead of relying on
the moving `develop` tag. Retain the previous image for rollback.

This release adds no database migration and does not change saved schedules,
rules, indexers, or download-client settings. Existing opt-in gates retain their
values. An outage hold resumes existing work when the client connection returns.

Repository privacy changes and historical retention limits are documented in
the [public metadata policy](public-release-metadata-policy.md). Follow
[SECURITY.md](../SECURITY.md) when reporting a vulnerability.
